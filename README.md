# DevRelay AI

DevRelay AI is an evidence-backed engineering handoff tool. It statically maps an authorized repository, uses NVIDIA Nemotron through Nebius Token Factory to produce an investigation plan, verifies plan citations against analyzed source evidence, and carries the result into a human-reviewable handoff. A separate, deterministic proposal preview is available only for one synthetic calculator scenario. No proposal is applied and repository code is not executed.

## Hackathon submission status

The current project workflow is: **authorized synthetic repository → static analysis → Nemotron investigation plan → schema and citation validation → plan review and handoff**. The calculator-only deterministic diff preview is a separate allowlisted workflow; it is not generated by Nemotron and is not a fix for the Northstar pipeline scenario.

The local sanitized telemetry database contains a successful Nebius Token Factory run for `continuity-pipeline-fixture` using `nvidia/Nemotron-3_5-Lightning`: HTTP 200, completed response, plan and citation validation passed, 5 verified references, 0 unsupported references, 4,652 input tokens, 906 output tokens, 0 reasoning tokens, and 6,277 ms latency. Its estimated cost was **$0.00049656**, calculated from the recorded usage and configured published rates. This is an estimate, not a provider invoice or a hard spending limit. Other attempts in the same history failed validation or were truncated; the run-history view distinguishes them from successful results.

Mock remains the default for local and automated tests. Mock output is labeled as simulated and must never be presented as a Nemotron result. A live request requires explicit provider selection, the separate live-inference switch, a configured server-side credential, and available durable request quota. Request quota limits call count, not dollars.

**There is no hosted judge-access URL.** The application stays loopback-only. A separate downloadable Windows test package is being prepared below; it runs locally with mock inference and is not a hosted application or precompiled installer. The GitHub source URL does not replace the separate working demo/test-build URL required by the hackathon. Do not expose the local services publicly without reviewed access controls and hosting. The final local video is `demo-recordings/submission-recording.mp4` (1920 × 1080, 2:42.5); it still needs to be uploaded publicly to YouTube, and the resulting URL added to Devpost. ## Quick start

Use Python 3.12 or newer and Node.js/npm for the dashboard. DevRelay is configured for local use: FastAPI listens on `127.0.0.1:8001`, and Next.js must be explicitly bound to `127.0.0.1:3000`. The application defaults to deterministic mock inference; live Nebius requests require explicit provider selection and a separate kill switch. The dashboard fails closed unless server-only Basic Authentication credentials and an exact `DEMO_AUTH_ORIGIN` are configured. Follow the Windows-specific [setup and production preflight](docs/windows-hosting.md); general dependency and API details are in [docs/setup.md](docs/setup.md).

The health check is available at `http://127.0.0.1:8001/health`. Repository analysis is available at `POST /api/v1/repositories/analyze`, and planning at `POST /api/v1/tasks/plan`; configure only authorized repository IDs as described in [docs/setup.md](docs/setup.md). API docs are available locally at `/docs` on the backend and must not be publicly exposed.

Phase 4B adds `POST /api/v1/proposals/create` for the predefined division-by-zero calculator task and `GET /api/v1/proposals/{proposal_id}` to retrieve a review-only proposal. Phase 7B allows either a server-validated mock or Nebius plan to continue only when its integrity, provider provenance, evidence and content-hashed analysis snapshot are verified. The proposal remains one deterministic, allowlisted in-memory diff; model output is never translated into code. Static checks use unified-diff validation and Python AST parsing. Runtime validation reports `not_run` because no trusted sandbox is configured. No proposal endpoint applies code.

Phase 5A adds a disabled-by-default local review workflow and evidence-based handoff reports. Set `ENABLE_LOCAL_REVIEWS=true` only in development to enable loopback review requests. Reviewer labels are unverified, and an approval only accepts a proposal for further consideration; it does not apply code. Review and report storage is process-local and non-durable. See [docs/setup.md](docs/setup.md) for safe local demonstration steps.

Phase 5B adds a separately disabled, loopback-only runtime-validation authorization and evidence workflow for the fixed synthetic calculator proposal. The current checkout has no trusted sandbox executor, so readiness fails closed and authorized attempts return `sandbox_unavailable`; **no repository tests or code are run**. Do not enable this feature expecting execution. See [docs/setup.md](docs/setup.md) and [docs/architecture.md](docs/architecture.md) for the threat model and current limits.

For offline planning, set `INFERENCE_PROVIDER=mock`. The deterministic mock supports only named synthetic evaluation scenarios; unsupported requests return an explicit unsupported result. It does not represent NVIDIA Nemotron output.

Live Nebius planning requires `INFERENCE_PROVIDER=nebius` and `NEBIUS_LIVE_INFERENCE_ENABLED=true`; mock remains the default even if an API key is present. Requests are bounded by prompt/output token limits, a timeout, one in-flight request, and a durable request-count quota. Truncated or malformed answers fail closed. No automatic retry or mock fallback is added. Successful plans expose sanitized provider/model, latency, and token-usage metadata. See [docs/inference-usage-and-demo-rehearsal.md](docs/inference-usage-and-demo-rehearsal.md) for telemetry behavior and the distinction between estimated cost and actual provider billing.

## Phase 8D.4 continuity scenario

The synthetic Northstar nightly-reporting fixture is a separate multi-file
Python repository for cross-module analysis. Configure its absolute path under
`continuity-pipeline-fixture` in `AUTHORIZED_REPOSITORIES` before selecting it
in the dashboard. The neutral request is in
`docs/continuity-pipeline-incident.md`; keep evaluator ground truth out of the
model prompt. Run `python -m scripts.phase8d4_evaluation` for offline static
analysis and bounded excerpt-selection measurements. Mock can exercise the
plan-only interface, but it does not interpret source semantics and is not
evidence of Nemotron reasoning. The local telemetry record includes one
successful live Nemotron plan for this fixture; consult the run-history screen
and [telemetry notes](docs/inference-usage-and-demo-rehearsal.md) for measured
usage and its estimate. Later failed attempts are visible separately. A
plan-only handoff and plan review are supported; reviewer labels are unverified
and records are process-local. The deterministic code proposal remains
calculator-only. See the [Phase 8D.5 runbook](docs/phase-8d5-evidence-handoff.md)
and [continuity storyboard](docs/phase-8d4-video-storyboard.md).

## Phase 7 demo and evaluation

Run the offline end-to-end evaluation against a temporary copy of the synthetic calculator fixture with the deterministic mock provider:

```powershell
Set-Location C:\devrelay-ai
.\.venv\Scripts\python.exe -m scripts.phase7_evaluation
.\.venv\Scripts\python.exe -m pytest
```

The evaluation JSON is checked in at `docs/evaluation/phase-7-results.json`. Mock metrics are kept separate from the historical live Nemotron observation; running the evaluation never contacts Nebius. Follow [docs/demo-script.md](docs/demo-script.md) for the full repository-to-handoff walkthrough and the offline fallback. No generated proposal is applied or executed.
